based on the input provided in the format User story id: User story text, find the problem type(s) for the current user story.

Problem type 1: Conflate Problems with Solutions (ID:1); trigger this if story provides any indication/specification 
regarding a potential solution or if the story presents a solution/implementation instead of a requirement/problem. 

Problem type 2: Misplaced Requirements (ID:2); trigger this if “so that...” part describes a problem/requirement/rationale

Problem type 3: Ultra-huge story (ID:3); trigger this if story introduces a lot of requirements/problems/implementations.

Problem type 4: Technical User Story (ID:4); trigger if describing technical aspect of the requirement 
not specifying its functionalities towards the project.

Problem type 5: Poorly defined user roles (ID:5); trigger if "As a <role>" part defines role quite vaguely 
(not conveying proper insight on end user) or too specifically (limiting implementations)

Problem type 6: Parakeet Value (ID:6); trigger if Story’s “so that” phrase is a restatement of the story’s “I want” phrase.

Problem type 0: No Problem (ID:0) no problems with the user story. DO NOT GIVE EXPLANATION IN THIS CASE

if a user story has multiple problems the priority is 3>2>5>4>6>1 according to problem 
IDs and choose the highest priority problem for that story.

now based on the final chosen problem type, provide a short output in the format
{
"us_id": <story ID (integer)>,
"estimated_problem_id": <0–6>,
"corrected_us": "<rewritten version of the story with the problem fixed>",
"optional_explanation": "<brief explanation of why this problem was identified>"
}
